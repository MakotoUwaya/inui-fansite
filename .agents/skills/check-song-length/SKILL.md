# 歌枠楽曲 開始・終了時刻 補正ワークフロー (check-song-length)

歌枠アーカイブに登録された楽曲データにおいて、タイムスタンプがアバウトであったり次曲の直前まで設定されている楽曲について、**yt-dlp によるピンポイント音声切り出しとエージェント（Gemini）による実音声試聴**により、1秒の狂いもなく正確な開始・終了時刻を特定・補正するためのスキルです。

---

## 🎯 コア判定基準・重要ルール

1. **カラオケのオケ（伴奏音楽）基準で厳密に判定**:
   - **開始時刻 (start)**: 歌い出し前の前奏・オケが鳴り始めた瞬間。歌う前の雑談や掛け声、曲振りトークが被っていても**オケの鳴り始め**を start とする。
   - **終了時刻 (end)**: 後奏・アウトロの余韻・オケの最後の音が完全に消え去った瞬間（または手動で停止・ブツ切りされた瞬間）。
     - **【超重要】ボーカル終了後に本人が「はい」「ふぅ」「ありがとう」等の感想・雑談を話し始めても、後ろでオケのアウトロ（ピアノやギターの余韻・伴奏）が流れている間は曲の途中である。トークの開始に惑わされず、オケの音が完全に消える瞬間を end とすること。**
2. **1動画1曲（単曲動画・MV）は調整不要**:
   - MVや歌ってみた等の1動画1曲コンテンツは、動画全体が1曲であるため調整対象外とする。複数曲が登録されている歌枠アーカイブのみを対象とする。
3. **外部DBからの曲長取得は廃止**:
   - 原曲音源の公式尺はVTuber歌枠のカラオケ音源（ワンコーラス、ショート版、アレンジ、長めの後奏カット等）と大きく乖離するため、外部DBへの問い合わせは行わず、実動画の音声を聴いて判定する。
4. **配信日（古い順）に1動画ずつ進行**:
   - ユーザーが管理画面（`/admin/songs`）で**「配信日（新しい順）」**から順次手動確認を進めるため、エージェントは**「配信日（古い順）」**から1動画単位で着実に進める（バッティング防止）。
5. **最重要制約: `is_length_checked` は変更しない**:
   - エージェントが補正した結果は、ユーザーが Web UI（`/admin/songs`）で最終確認・承認するため、DB更新時は `end`（必要に応じて `start`）のみを更新し、**`is_length_checked` は `false` のまま維持**する。
6. **一時音声の即時クリーンアップ**:
   - 切り出した音声クリップ（`tmp/audio-clips/*`）は試聴・特定完了後に速やかに削除する。

## 🖥️ 管理画面（Web UI）

```bash
# 開発サーバー起動
pnpm dev

# アクセスURL: http://localhost:3000/admin/songs
```

- **ショートカットキー**:
  - `Space`: 再生 / 一時停止
  - `1`: 歌い出し確認 (±0s)
  - `2`: 歌い終わり確認 (前3s)
  - `3`: 現在位置を開始時刻にセット
  - `4`: 現在位置を終了時刻にセット
  - `Ctrl + Enter`: 確定して次の曲へ進む

## 📋 1動画ごとの補正手順

### ステップ 1: 最も古い未チェック歌枠動画を1本抽出
DBから未チェック曲を含む「配信日（古い順）」の歌枠動画を1本特定し、その全楽曲リストを取得。

### ステップ 2: 各曲の終了付近を yt-dlp でピンポイント切り出し
- 各曲の `end`（または次曲 `start`）の手前〜直後（約40〜60秒）をピンポイントで切り出す。
- yt-dlp コマンド例:
  ```powershell
  & 'C:\Users\makot\ghq\github.com\ErrorFlynn\ytdlp-interface\bin\yt-dlp.exe' --extractor-args "youtube:player_client=android" -x --audio-format mp3 --download-sections "*<START_SEC>-<END_SEC>" "https://www.youtube.com/watch?v=<VIDEO_ID>" -o "tmp/audio-clips/range-<VIDEO_ID>-<START>_<END>.%(ext)s"
  ```

### ステップ 3: 音声試聴によるオケ終了秒数の特定
- 切り出した mp3 を `read_file` 等で試聴。
- 歌唱パート終了後、オケ（伴奏）が完全に消える秒数、およびトークが始まる秒数を聴き取る。
- **オケが完全に終了した秒数**を `end` とする。

### ステップ 4: DB更新とファイル削除
- 特定した `start` / `end` を `singing_stream` に更新（`is_length_checked` は `false` を維持）。
- 音声クリップを削除。
- 1動画内の全曲が完了したら、ユーザーに結果を報告する。
  - **重要**: 時刻の報告は秒数単体ではなく、必ず **`hh:mm:ss`（例: `00:09:56` 〜 `00:14:09`）** のタイムコード形式で表記すること。
